SECTION 01The problem: one session, three tasks

A real session — 2055c1f8 — started as "check my open tickets", then drifted into an unrelated data investigation, then into a bug fix in another area. Three unrelated threads in one transcript.

When it came time to find it again, /resume was no help: its picker shows an auto-summary, and it can't full-text search what was said inside a session. The work was effectively buried.

⚠
The root cause isn't recovery — it's scope.

A session that tries to be three sessions is unfindable and its context gets muddy. The fix is one task per session, each tagged so it's findable later.

SECTION 02One slug, everywhere

Pick a short kebab slug per task — no-show-fallback, zif-trace. Use that one identifier in three places, so the task is recognizable no matter where you look.

Slug → three destinations
Hover a box to trace its link. The slug is the single thread tying the task together.
💡
Why it works

claude -n <slug> sets the prompt box, the /resume picker entry, and the terminal title at once. Add a matching branch/worktree and the slug spans your whole environment.

SECTION 03The task lifecycle & commands

Start each task with a named session; close it whenever; reopen it any of three ways depending on what you remember.

Where this lives

The helpers are in ~/bash/.bash_functions/claude.sh (auto-sourced). Session transcripts persist under ~/.claude/projects/<project>/<uuid>.jsonl for cleanupPeriodDays (bumped to 90).

SECTION 04The memory ecosystem

Recovery is only the first layer. As work settles, it distills into progressively more durable, more searchable forms — and each recall tool reaches a different layer.

From volatile transcript to durable, searchable knowledge
The live transcript fades (90 days); claude-mem keeps a searchable, structured record; this knowledge base reads from it.
  • Live transcript — the full JSONL of a session. Reachable with cont, cresume, cfind. Expires after 90 days.
  • claude-mem — observations & session summaries captured into a searchable SQLite store (~/.claude-mem/). Reached with mem-search. Persistent.
  • Auto-memory — the curated MEMORY.md notes, loaded into every session automatically.

SECTION 05Your knowledge base

The bottom layer — claude-mem — holds thousands of observations and session summaries from your past work. The knowledge base makes it browsable: a graph of how sessions, observations, files and concepts connect, plus full-text search across everything.

Local & live

A small FastAPI backend (python app.py) reads ~/.claude-mem read-only and stays current as you work — keyword and semantic search run server-side, and an SSE channel refreshes the page when new entries land. Nothing is written back, nothing leaves your machine.
